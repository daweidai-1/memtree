# 可直接复制的提示词片段

## 1. 上下文注入（每轮放在 system 或对话最前面）

```text
## 长期记忆（时间轴记忆库，已按时间覆盖）
{{ context 命令输出，含最后一行 ※ 图例 }}

使用规则：
- ■ 开头的是当前有效状态，可以直接当作事实。
- 括号里的 (曾:…) 是已废弃的墓碑，只能用于解释"以前是怎样"，绝不能当现状。
- ◇ 是本分支上还没验证的假设，只能当"待验证"，不能当结论。
- ○ 是尚未合并的探索分支，只代表"在试"，不代表"已定"。
- 记忆里没有的，就说不知道，不要用常识补。
- 回答涉及"以前"时带上时间，例如"9 月中旬定的是 5 分钟 K 线"。
```

## 2. 从对话抽取记忆节点（写路径用）

```text
从下面这段对话里抽出值得长期记住的节点。每个节点输出一行 JSON：
{"type":"fact|pref|decision|event|hypothesis","subject":"域.属性 或 null","content":"≤40字陈述","ts":"YYYY-MM-DD","outcome":-1.0~1.0}

判断标准：
- fact/pref：用户的稳定属性、偏好、习惯，未来对话还会用到 → 必须给 subject
- decision：用户明确拍板的选择 → 必须给 subject（同一件事用同一 subject，才能覆盖旧的）
- event：做过的动作、发生的事，一般不需要 subject
- hypothesis：只是"如果/试试/也许"，不是结论 → 标记出来，会开到分支里
- outcome：这件事的结果值。成功/有效=+0.5~+1，失败/无效=-0.5~-1，中性=0。
  它进"虚轴"，以后可以按"当时成功/失败"精确定位；漏填等于丢掉一维。

不要抽取：寒暄、一次性的临时指令、工具输出、你自己说的话。
宁少勿滥：拿不准就不抽。
```

## 3. 压缩旧记忆（生成因子标记）

```text
把下面 N 条历史事件压成一句 ≤30 字的陈述，要求：
1. 保留结论和结果（"方案A失败，因内存泄漏"），删掉过程细节；
2. 保留时间跨度，格式 "9月上旬~9月中旬"；
3. 已被后续否定的内容，用"（已否）"标注，不要写成现状；
4. 不要新增原文没有的信息。

输出一行，直接作为 summary 节点的 content。
```

## 4. recall 结果转述规则

```text
检索结果里的状态标记必须原样保留语义：
- ● active → 可以说"你现在…"
- ◐ superseded → 只能说"你以前…，后来改成了…"
- ○ archived → 只能说"当时的结论是…（分支已归档）"

禁止把 ◐ 和 ○ 的内容直接说成用户的现状。
```

## 5. 触发分支的信号词

| 用户说法 | 动作 |
|---|---|
| "如果当初…""要是…会怎样""换个思路试试" | `branch try-<n> --from <相关历史节点>` + `checkout` |
| "先这样试试，不行再说" | 在分支里 `commit --type hypothesis` |
| "算了，还是按原来的" | `checkout main`，分支保留不合并 |
| "这版不行，问题在 X" | `merge <分支> --summary "结论：…因X不可行"` |

## 6. 每轮结束时的自检（3 秒，不要再跑 context）

- 这轮用户有没有**推翻**之前的某个状态？→ `commit` 同一 subject，让时间覆盖生效
- 这轮有没有产生**新结论**？→ `commit --type decision`
- 分支写着写着忘了回主干？→ 看 `commit` 返回 JSON 里的 `branch` 字段。

  **不要为此再跑一次 `context`** —— 那是每轮双倍注入成本（约 +550 token/轮），
  而 `context` 每轮本来就已经注入了，HEAD 就在第一行。
