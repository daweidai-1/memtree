# 数学形式与推导

> 这份文件是给"想改算法"的人读的。Agent 执行命令不需要它——`SKILL.md` 里那句话就够了。

## 1. 一条记忆是什么

```
M = z ⊗ e        z = t + i·r     实轴 t = 时间，虚轴 r = 结果
Q = z_q ⊗ e_q
```

打分：

```
⟨Q, M⟩ = Re(z̄_q · z_m) · ⟨e_q, e_m⟩
       = (t_q·t_m + r_q·r_m) · cos(e_q, e_m)
```

三个部分各管一件事：

| 项 | 作用 | 范围 |
|---|---|---|
| `t_q·t_m` | 时间权重，不是匹配 | (0, 1] |
| `r_q·r_m` | 结果对齐度；`r_q=0` 时恒 0 | [-1, 1] |
| `cos(e_q, e_m)` | 语义相似度，唯一真正的"匹配" | [-1, 1] |

## 2. 为什么时间不做匹配，只做权重

查询永远站在某一个时刻（默认"现在"），所以 `t_q` 是**唯一值**，不是向量。归一化后 `t_q ≡ 1`，于是：

```
t_q·t_m  →  t_m  =  2^(-Δt/45天)
```

一条严格单调的衰减权重。因此问"我喜欢吃什么"时：

```
⟨Q, M⟩ = 2^(-Δt/45) · cos(e_q, e_m)
```

语义相似度 × 新鲜度，最大值自然落在最新那条——**不需要任何额外的排序规则**。这是"时间是第一索引"在数学上的字面实现。

## 3. 为什么虚轴平时休眠

`r_q` 默认 0，`r_q·r_m = 0`，整项消失，打分退化成"语义 × 新鲜度"。

只有传 `--outcome` 时才激活：问"当初哪个方案成功了"，`r_q = +0.9`，于是结果值为负的记忆被倒扣。**虚数用来定位结果**——这是字面意思，不是比喻。

## 4. 为什么覆盖不看结果值

覆盖只回答"现在是什么"，其它维度只服务检索。一旦让可信度/结果值参与覆盖，就要定义"多少次确认能压过多新的改口"，规则会迅速复杂化且不可预测。

`(subject, 时间)` 完全相等即可判定，这是确定性的：**同样的输入永远同样的输出**，不调 LLM，可复现、可审计。

## 5. 时间旅行

`--at <时刻>` 时，覆盖关系按"当时"重算：该时刻之前、同 subject 中 `t` 最大的节点是「当时现状」，其余标「当时已过时」。

不硬过滤未来节点——事件的结果可能在事后才确定；但 subject 的状态严格按当时算。

只给日期（`len(str) <= 10`）时按当天 23:59:59 计，否则当天白天发生的事会被判成"未来"。

## 6. 语义向量的实现现状

`text_vec()` 是 128 维稠密 ±1 随机投影的**词袋**，零依赖、可解释，但只是**词面近似**，做不到语义泛化。

换成真嵌入时（见 `schema.md` 第 8 节）：把 `text_vec()` 换成调 embedding 服务，仍返回 128 维并 L2 归一化，其余逻辑（时间权重、结果项、覆盖、分支）一行都不用改。

**注意：向量必须稠密。** 稀疏哈希会让大量维度恒为 0，点积失去区分度——这是实测踩过的坑。

## 7. 复杂度

| 操作 | 复杂度 |
|---|---|
| `commit` | O(N)（同 subject 比较） |
| `recall` | O(d·N)，d=128 |
| `context` | O(N log N)（按权重排序后裁剪） |

每条记忆存储：`t`(8B) + `r`(8B) + 事件向量(512B) ≈ 530 字节，正文另存于 `blobs`。
